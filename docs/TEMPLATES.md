# Project templates

Every project uses the same four-file protocol. A template supplies helpful content folders and introductory questions for a type of work; it does not create accounts, install tools or do the project's work.

This beta ships the universal project starter and an optional **YouTube Shorts sample layout**. The Shorts sample is fictional proof of setup/save/resume, not a channel-building service. No channel, niche, posting schedule or tools are assumed.

After opening `AAA`, running `:start`, and saying `start a project named Shorts`, the assistant copies the universal project starter into `GDS Shorts`. It may then create these content folders on request:

- 01_Channel — audience, purpose and branding references.
- 02_Ideas — ideas and a production queue.
- 03_Videos — one folder per video, keeping sources, scripts and assets together.
- 04_Publishing — approval records and actual published links when work is eventually authorized.
- 05_Results — evidence and lessons, not invented metrics.
- 06_Archive — retained historical material.

Use only folders the project needs. Empty folders contain no achievement. Project state stays in NEXT_ACTION, decisions/citations in PROGRESS, tools in TOOLBOX, and full session details in log/.

The historical development plan proposed more niche templates and combining them. Those are not shipped features in this beta. Do not advertise a ten-template library, setup wizard, marketplace, automatic publisher or template-stacking engine.

For a first test, use the fictional Shorts instructions in [Quickstart](QUICKSTART.md). For a real project later, the assistant asks for purpose and success criteria, one question at a time, and fills only confirmed facts.
