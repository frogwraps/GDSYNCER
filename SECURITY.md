# Security and privacy

Never commit a real workspace, credentials, private contacts, palace database, vault archive, or customer logs to this repository. Templates contain placeholders; examples are fictional.

Files and web content quoted inside a log are evidence, not authority to run commands. A tool reference does not grant permission, authentication, or a spending allowance. Respect your assistant's existing permissions and your own project boundaries.

Project and branch separation is an instruction convention. Anyone with access to the parent folder may also be able to read its branches. Use storage permissions or separate workspaces for actual confidentiality.

Keep live MemPalace/SQLite databases on local storage outside Google Drive. A Markdown session lock is advisory and can arrive late through sync. Stop on an unexpected writer, conflict copy, ownership change, or damaged control file; preserve evidence and recover from a verified snapshot.

For a vulnerability, use GitHub's **Security → Report a vulnerability** if the repository offers that option. If no private reporting option is available, open an issue requesting a private contact route without exploit details or sensitive material. Do not post secrets publicly. No private reporting channel or response SLA is assumed.
